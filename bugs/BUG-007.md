# BUG-007 Framework errors (unknown route, wrong method, unhandled 500) bypass the error envelope

| Field | Value |
|---|---|
| Severity | S3 Minor |
| Priority | Low |
| Status | Closed (verified) |
| Affects version | 0.1.0-rc1 |
| Fix version | 0.1.0-rc2 |
| Component | API |
| Requirement | REQ-API-01 |
| Found by | TC-API-006, Newman collection-level envelope check |
| Environment | Build 0.1.0-rc1 (tag v0.1.0-rc1), Python 3.13, FastAPI 0.143, SQLModel 0.0.48, Ubuntu 24.04 |
| Reported by | Luis A. Quiroz |

## Steps to reproduce

1. `GET /nope`.
2. `DELETE /health`.

## Expected result

404 and 405 with `{"error": {"code", "message", "details"}}`.

## Actual result

`{"detail": "Not Found"}` and `{"detail": "Method Not Allowed"}`. Unhandled exceptions return a plain-text `Internal Server Error` body, which Newman's envelope check also flagged.

## Impact

Clients that parse `error.code` break on these responses.

## Root cause

Only `ApiError` and request validation errors had handlers. Starlette's HTTP exceptions and unexpected exceptions used the framework defaults.

Fix: `fce56c1`.

## Verification

TC-API-006 passes and Newman's collection-level envelope check passes on all 61 requests.
